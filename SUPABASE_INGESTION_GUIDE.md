# Supabase (PostgreSQL) Ingestion & Ollama Context Guide

This guide details the exact architecture and instructions for shifting storage from local files to **Supabase (PostgreSQL)**, structuring clean HTML into relational tables, and using **Relational Context Retrieval** for Ollama.

---

## 1. Database Schema (No `pgvector`)

As specified, **`pgvector` is completely skipped**. Regulatory change management requires deterministic, exact verbatim text-to-text matching (Mode A alignment via `ref_path` and Mode B patch replacement).

The schema is defined in [`supabase/schema.sql`](file:///C:/Users/samar/OneDrive/Desktop/Azentio/source_monitoring/supabase/schema.sql) and [`supabase/migrations/20261031_create_regulatory_tables.sql`](file:///C:/Users/samar/OneDrive/Desktop/Azentio/source_monitoring/supabase/migrations/20261031_create_regulatory_tables.sql):

### Hierarchical Tables
1. **`public.reg_documents`** (Metadata: title, authority, region, jurisdiction, source URL, effective date)
2. **`public.reg_sections`** (Chapters / Headings as `cp1`)
3. **`public.reg_paragraphs`** (Individual clause text blocks as `cp2` with `ref_path`)

### Step 1: Run the Migration in Supabase
Open your **Supabase Dashboard &rarr; SQL Editor &rarr; New Query**, paste the contents of [`supabase/schema.sql`](file:///C:/Users/samar/OneDrive/Desktop/Azentio/source_monitoring/supabase/schema.sql), and click **Run**.

## 4. Passing Context to Ollama (Relational Context Retrieval)

Because local models (Llama 3.1, Qwen 2.5) perform best with targeted inputs rather than huge documents, we use **Relational Context Retrieval**.

### Querying Targeted Paragraphs from Supabase
```typescript
import { getSupabaseClient } from './src/supabase/client';

const supabase = getSupabaseClient();

// Fetch all paragraphs for a given document ordered deterministically
const { data: paragraphs, error } = await supabase
  .from('reg_paragraphs')
  .select('*')
  .eq('doc_id', docId)
  .order('ref_path', { ascending: true });
```

### Passing to Ollama with [`ollamaContextService`](file:///C:/Users/samar/OneDrive/Desktop/Azentio/source_monitoring/src/ai/ollama-context.ts)
```typescript
import { ollamaContextService } from './src/ai/ollama-context';

// Fetch target clause ref_path and build Ollama prompt payload
const { payload } = await ollamaContextService.buildClauseComparisonPrompt({
  oldDocId: 'rbi-2024-25-87',
  newDocId: 'rbi-2025-12-34',
  refPath: 'sec-4/para-4.1',
  model: 'llama3.1'
});

// The prompt injects clean text within untrusted delimiters:
// [OLD_CLAUSE]:
// Banks may use AI tools for credit assessment...
//
// [NEW_CLAUSE]:
// Banks may use AI tools for credit assessment, subject to stricter risk management framework...
```

### Deterministic Span Verification
Pass any response span generated by the LLM through `verifySpan` to ensure 100% compliance:
```typescript
const isValid = ollamaContextService.verifySpan(
  newPara.text,
  llmResponse.exactAddedSpans[0]
);
// Returns true only if the span exists verbatim in the source text
```
